The Grid

The S.I.E.R.R.A data service: wildfire, evacuation, weather, earthquake, road, power and mesh-network data for the Ebbetts Pass / Highway 4 corridor of the central Sierra, in one public API.

public · read-only · keyless · /api/openapi.json

# What this is

Pollers read the upstream sources (CAL FIRE and FIRIS, Cal OES evacuation zones, the National Weather Service, USGS, CHP, Caltrans, PG&E, county burn lines and MeshCore community bridges), normalize every occurrence into one event model, and keep its full revision history. You read the result here. It is run by S.I.E.R.R.A, the Signal Integrity & Emergency Radio Response Alliance, a volunteer group.

This page is for people and agents building on the API. To browse the data, use the explorer at grid.sierragridteam.org.

# Principles

  • One surface. Everything is under /api/v1, defined in protobuf and served as JSON. Field names are camelCase; query parameters take camelCase (as the spec names them) or snake_case.
  • Events are the unit. Every wildfire, closure, alert or outage is an event with an id, a severity (INFO to EXTREME), a status and a revision number. Each content change writes a new revision, and the history stays queryable.
  • Places by slug. Areas, counties, towns and corridors are addressed by slug, such as ebbetts-pass or calaveras-county.
  • Fail loud. Every source reports sourceStatus: OK, STALE or UNAVAILABLE. A failed feed is returned as a failure, never as a fabricated all-clear, and null means unknown, not zero.
  • Cache-friendly. Reads carry Cache-Control: public, max-age=30 (map layers 60); most also carry an ETag, so a conditional GET with If-None-Match returns 304.
  • Open to browsers. CORS is open for GET, and no key or signup is needed. The one authenticated write endpoint exists only for operator-run monitors and reporters.

# Start here

$ curl https://data.sierragridteam.org/api/v1/sources
# every upstream feed and its health

$ curl https://data.sierragridteam.org/api/v1/places/ebbetts-pass/summary
# the corridor right now: severity rollup, evacuations, top events

$ curl 'https://data.sierragridteam.org/api/v1/events?place=ebbetts-pass&layer=road_incident'
# active and scheduled road incidents and closures

Conventions:
- All data is read-only GET under /api/v1. No key. JSON is camelCase;
  query parameters take camelCase or snake_case (pageToken, page_token).
- Places are addressed by slug (ebbetts-pass, calaveras-county). List them
  with GET /api/v1/places; resolve a point with /api/v1/places:resolve.
- /api/v1/events defaults to status=ACTIVE,SCHEDULED. Pass status
  explicitly for other states, and always pass place: unscoped, the
  feed is mostly INFO mesh-radio nodes.
- Severity runs INFO, MINOR, MODERATE, SEVERE, EXTREME.
- Timestamps are RFC 3339 in UTC.
- Pass geometryFormat=OBJECT to get geometry as a GeoJSON object instead
  of base64 bytes. Coordinates are [lng, lat].
- Lists page with a keyset cursor: send nextPageToken back as pageToken
  until it comes back empty. A short page is not the end.
- Send If-None-Match with a stored ETag; a 304 means nothing changed.
  Responses are cacheable for 30 seconds; poll every 30-60 s at most.
- On 503 with Retry-After (a deploy handover), wait and retry.
- Check sourceStatus. UNAVAILABLE or null means unknown: never present it
  as zero or as an all-clear. Show each record's attribution.

Do not:
- call the write endpoint (POST /api/v1/ingest/*); it is for operators.
- scrape or proxy the upstream feeds through this service.
- send a generic User-Agent; name your app and a contact.

# Etiquette

  • Cache responses and revalidate with If-None-Match. Most sources update every one to ten minutes.
  • Poll every 30 to 60 seconds at most. If you get a 503 with Retry-After (a deploy handover), wait that long and retry.
  • Say who you are in User-Agent, with a URL or email.
  • Show the attribution string and link the upstream source wherever you display the data. Evacuation data is reference only; point people to official sources.

A fuller documentation site is planned. Until then, the OpenAPI spec is the reference. Questions: sierragridteam.org.
